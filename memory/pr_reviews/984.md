## Findings

### F1: Joined widget play's origin is untested  (fixed)

- **severity:** Warning
- **status:** fixed
- **location:** PodHaven/Play/PlayManager.swift:509 (scope: in-diff)
- **concern:** `.requested(origin:requestID:)` carries a widget play that joins a load into `beginPlaybackRequest`, so widget route-stall recovery still starts, but no test failed when that origin was dropped.
- **resolution:** Added "a widget play during a cached load recovers buffering after the load" to `RouteChangeRecoveryTests`; it fails when the origin becomes `.application` and passes with the PR's code.
- **fixed_at:** 2026-11-09

### F2: A play before a newer load claims its transition joins the old load  (skipped)

- **severity:** Warning
- **status:** skipped
- **location:** PodHaven/Play/PlayManager.swift:610, PodHaven/Play/PlayManager.swift:164 (scope: in-diff)
- **concern:** While on-deck recovery holds another episode, `load()` awaits the recovery lookup after `play(C)` sets its pending play but before it claims the transition, so a `play()` in that window joins the old loading episode, overwrites C's pending play, and `play(C)` returns `.unavailable` with C paused.
- **resolution:** Deferred to a follow-up, not fixed: the window is one database read during an active on-deck recovery for another episode, the behavior before this PR failed in the same window, and closing it changes how `load()` hands over ownership.
- **follow_up_issue:** https://github.com/jubishop/podhaven/issues/1049

### F3: A superseding plain load leaves an older pending play  (skipped)

- **severity:** Nit
- **status:** skipped
- **location:** PodHaven/Play/PlayManager.swift:153, PodHaven/Play/PlayManager.swift:498 (scope: related)
- **concern:** When a plain `load(C)` supersedes B's load after a pending play for B, `finishLoadTransition`'s ownership guard skips B's pending-play cleanup, so a failed C load leaves `.play(B)` behind; the join path adds `load(B)` followed by `play()` to the existing `play(B)` route.
- **resolution:** Skipped. The only plain-load caller that can overlap is the episode detail play-at-time flow, and only its failure leaves the pending play. The effect is one toggle that pauses instead of playing, or a CarPlay "not ready" message, and it clears itself on the next play or pause.
