## Findings

### F1: Discovery list shows misleading "worked through all picks" empty state after collector reset

- **severity:** Warning | **status:** fixed
- **location:** SearchDiscoveryListView.swift; SearchViewModel.disappear(); SearchRecommendationCollector.reset()
- **concern:** Tab switch clears collector cache but a pushed SearchDiscoveryListView persists on the nav path, rendering falsely "exhausted" empty state — permanently for search-sourced lists
- **outcome:** `disappear()` sets `navigation.search.path = []` — Search always reopens at root; trending chip persists via `currentTrendingSection` view-model state
- **resolution:** Nav-path splice rejected as hack; refresh-waste on every Search return accepted as pre-existing / orthogonal
- **fixed_at:** 2026-05-31

### F2: `visiblePicks` is a test-only production API

- **severity:** Nit | **status:** fixed
- **location:** SearchRecommendationCollector.swift:816-819
- **concern:** `visiblePicks` has no production callers (~30 test assertions only) — CLAUDE.md rule against test-only production surfaces
- **outcome:** Deleted from production; identical test-target extension in SearchRecommendationCollectorTestHelpers.swift
- **fixed_at:** 2026-05-31

### F3: Caching a discovery pick removes it in-memory but it resurrects on the next Search visit

- **severity:** Nit | **status:** fixed
- **location:** SearchRecommendationCollector.isDiscoveryCandidate; ManagingEpisodes cacheEpisode/saveEpisodeInCache
- **concern:** `cacheEpisode`/`saveEpisodeInCache` call `didPerformAction`→`removePick` without gating `isDiscoveryCandidate`, so cached picks reappear after reset/re-drain
- **outcome:** Reverted `isDiscoveryCandidate` cache gate; dropped `didPerformAction` from `cacheEpisode` and `saveEpisodeInCache` — caching non-consuming like tags
- **resolution:** Gate must stay aligned with canonical `Episode.candidate`; cached episodes still appear in topRecommendations/UpNext
- **fixed_at:** 2026-05-31

### F4: SearchRecommendationCollector concurrency complexity (maintainability)

- **severity:** Nit | **status:** fixed
- **location:** SearchRecommendationCollector.swift (whole file; esp. drain/cache lifecycle)
- **concern:** Hand-rolled concurrent state machine (`queued`/`inFlight`/`pickIndex`/`typedSearchGeneration`/detach guards) — high cognitive load and maintenance risk despite being correct
- **outcome:** Updated issue #356 with re-review insights; no code change in this PR
- **resolution:** Tracked in #356; accept complexity for v1
- **fixed_at:** 2026-05-30

### F5: Typed searches don't survive a tab switch (user-requested enhancement)

- **severity:** Nit | **status:** fixed
- **location:** SearchViewModel.swift (appear/disappear); Debouncer.swift
- **concern:** `disappear()` called `searchDebouncer.reset()`, clearing typed query on tab switch while trending chip already persisted
- **outcome:** Added `Debouncer.cancelPending()`; `disappear()` preserves query, `appear()` re-runs search via `refreshSearch()` when one survived
- **fixed_at:** 2026-05-31

### F6: `cachingDiscoveryPickIsNonConsuming` test races resume(), crashes test process (CI red)

- **severity:** Critical | **status:** fixed
- **location:** SearchRecommendationCollectorRemovalTests.swift:296-298
- **concern:** F3 regression test calls `simulateBackgroundFinish` without `waitForResumed` first — `FakeURLSessionDownloadTask.assertResumed` fatalError under parallel CI load, cascading ~50 unrelated test failures
- **outcome:** Inserted `waitForResumed(taskID)` between `waitForDownloadTask` and `simulateBackgroundFinish`
- **resolution:** Fixture-invariant violation in new test, not a production defect
- **fixed_at:** 2026-05-31
