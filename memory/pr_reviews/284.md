### F9: Pending typed search can survive tab switch as visible text with trending results underneath

- **severity:** Warning | **status:** fixed
- **location:** SearchViewModel.swift:264; SearchViewModel.swift:683; Debouncer.swift:55
- **scope:** related to in-diff behavior
- **confidence:** high
- **concern:** `disappear()` cancels the pending debounce while preserving `currentValue`; if the user switches tabs before the debounce fires, `searchedText` remains old/empty and `appear()` treats the screen as trending.
- **impact:** Search can reopen with a query still visible in the field but no matching query execution, leaving trending or old results until the user edits the text again.
- **recommendation:** Flush/apply the pending value or compare trimmed `searchText` to `searchedText` on `appear()` so the visible query is the source of truth when restoring Search.
- **outcome:** Added `Debouncer.cancelPendingAndCommitCurrentValue()` and use it from `SearchViewModel.disappear()` so `appear()` restores the visible query through the existing search rerun path without firing search work during teardown.
- **regression:** `SearchViewModelTests.pendingTypedSearchSurvivesTabSwitch` failed before fix with `searchedText` empty, `searchText` `growth`, and zero results.
- **test_plan:** `bin/lint-swift-format`; `xcodebuild test -project PodHaven.xcodeproj -scheme PodHaven -destination 'platform=macOS,name=My Mac' -only-testing:PodHavenTests/DebouncerTests -only-testing:PodHavenTests/SearchViewModelTests`
- **fixed_at:** 2026-06-03

### F10: Existing discovery picks stay visible after scoring context becomes unavailable  (skipped)

- **severity:** Warning | **status:** skipped
- **location:** SearchRecommendationCollector.swift:512-532 (watcher); :863-877 (bannerState)
- **scope:** in-diff
- **concern:** Watcher only handles closed→open; `bannerState(for:)` returns `.loaded` whenever picks exist, before the `.unavailable` check — so stale picks/banner persist if the engine context closes while Search stays alive.

### F12: Cancelled trending fetch can leave Search stuck loading  (fixed)

- **severity:** Warning | **status:** fixed
- **location:** PodHaven/Views/Search/Models/SearchViewModel.swift:299; PodHaven/Views/Search/Models/SearchViewModel.swift:677
- **scope:** related
- **concern:** cancelling a trending fetch leaves `TrendingSection.state == .loading` with `task == nil`
- **issue:** `disappear()` cancels and nils trending tasks, but cancellation returns before resetting `.loading`; `appear()` then refuses to refetch because `.loading` is treated as already active work.
- **impact:** leaving Search while top/trending podcasts are loading can reopen to an indefinite "Fetching top..." state with no task running.
- **outcome:** `disappear()` resets cancelled `.loading` trending sections to `.idle`, so the next `appear()` starts a fresh fetch.
- **test_plan:** `SearchViewModelTests.disappearClearsStuckTrendingLoadingState()` failed before the fix and passed after; full `SearchViewModelTests` suite passed after.
- **fixed_at:** 2026-06-04
