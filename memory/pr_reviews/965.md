## Findings

### F1: A duration that rounds to 2^63 seconds crashes every formatter that shows it  (fixed)

- **severity:** Critical
- **status:** fixed
- **location:** PodHaven/Extensions/CMTime.swift:49, PodHaven/Extensions/TimeInterval.swift:62 (scope: in-diff)
- **concern:** The `Double` parser accepts values such as `9223372036854775808` and `9.2233720368547758e18`, which `main`'s `Int` parse rejected. `CMTime(seconds:preferredTimescale:)` saturates them to `Int64.max` at timescale 1, a numeric time, so the `isNumeric` guard keeps them. `CMTime.timeComponents` and `TimeInterval.formattedParts` then trap in `Int(_:)`, crashing the episode list row, CarPlay detail, and the queue and now-playing widgets each time they render the episode. `main` already stored `9223372036854775807` this way.
- **resolution:** Both formatters now convert with `Int(exactly:)`. A `CMTime` whose seconds don't fit in `Int` describes as `Unknown`, as non-finite ones already did, and such a `TimeInterval` formats as zero. The fix also covers durations `main` already stored, which a later refresh with an invalid value keeps. Before it, both new suites crashed the test host in `Int(_:)`.
- **fixed_at:** 2026-11-24
