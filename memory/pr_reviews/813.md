## Findings

### F1: Overlapping share exports can delete each other's staging file  (skipped)

- **severity:** Warning
- **status:** skipped
- **location:** PodHaven/Database/AppDB.swift:258
- **concern:** Each export removes every entry but the snapshot from the shared directory without serialization, so two overlapping `FileRepresentation` exports could remove each other's staging file.
- **resolution:** Skipped: overlap needs the system to run the export closure twice at once, which the modal share flow makes unlikely; the swap stays atomic, so the cost is one failed debug share the user can retry, which does not justify lock state and a hard-to-test race.

### F2: Earlier builds' export snapshots stay in tmp  (skipped)

- **severity:** Nit
- **status:** skipped
- **location:** PodHaven/Views/Settings/DebugSection.swift:406
- **scope:** related
- **concern:** The fix bounds new exports, but `tmp/<uuid>/db.sqlite` copies from earlier builds' exports remain on devices that exported before it.
- **resolution:** Skipped: the count is finite and rare, the OS may purge `tmp`, My Mac had none, and `CacheBackgroundDelegate` also writes UUID-named `tmp` entries, so a launch-time sweep adds deletion risk for little gain.
