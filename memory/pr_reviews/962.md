## Findings

### F1: Non-refresh RSS writes keep the stored feed validators  (skipped)

- **severity:** Warning
- **status:** skipped
- **location:** PodHaven/Database/Repo.swift:641 (scope: related)
- **concern:** `upsertPodcastEpisodes` rewrites an existing podcast's and episode's RSS columns from in-memory feed data but keeps `feedETag`, `feedLastModified`, and `feedValidatorsBuild`. If that data is older than the last applied refresh, the next refresh gets a 304 and no longer corrects it.
- **resolution:** Skipped. It needs a user action on an unsaved episode whose in-memory feed parse predates a newer refresh of the same saved podcast, which is rare. The harm is stale metadata that heals when the feed next changes or on the next app build. Clearing the validators in the upsert's update assignments is small, but it needs its own regression test and another full validation run, which the risk doesn't justify.
