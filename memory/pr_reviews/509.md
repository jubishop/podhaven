## Findings

### F1: Failure cleanup can outlive background-session completion  (decided)

- **severity:** Warning
- **architecture:** false
- **confidence:** high
- **location:** PodHaven/Cache/CacheBackgroundDelegate.swift:349
- **scope:** related
- **concern:** didCompleteWithError spawns untracked async cleanup, allowing background-session completion to run first
- **issue:** The synchronous error callback returns after launching a Task without registering it in finalizations.
- **impact:** iOS can suspend before downloading is cleared and the latch is signaled, leaving a failed episode stuck until next-launch reconciliation.
- **recommendation:** Protect error cleanup with the same per-session finalization lifecycle as successful downloads.
- **test_plan:** Park the error callback's episode fetch and assert completion plus the background assertion remain pending until cleanup drains.
- **status:** decided
- **decision:** fix in PR
