## Findings

### F1: Rejected anchor nested in an allowed one keeps the outer link  (skipped)

- **severity:** Nit
- **status:** skipped
- **location:** PodHaven/Views/Components/HTMLContent.swift:504 (scope: related)
- **concern:** A rejected href pushes nothing onto `FormatStack.linkStack`, but its `</a>` still pops, so in invalid nested markup like `<a href="https://a">X <a href="tel:1">Y</a> Z</a>` the text Y takes the outer link and Z loses it.
- **resolution:** This needs invalid nested anchors, and the only link it can attach is the author's own allowed one, so no disallowed scheme becomes reachable. Href-less nested anchors already behaved this way before the PR. Pushing an optional URL for each anchor would fix it, but that costs a parser change, a test, and another full validation run for a cosmetic edge case.
