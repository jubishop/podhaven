### F13: Transcription work cannot be cancelled  (decided)

- **severity:** Warning
- **architecture:** true
- **confidence:** high
- **location:** PodHaven/Views/Episodes/ViewModifiers/EpisodeSwipeViewModifier.swift:28; PodHaven/Transcriptions/TranscriptionProcessor.swift:95
- **scope:** in-diff
- **concern:** transcription actions enqueue persistent work without any user cancellation path
- **issue:** queued and active jobs cannot be stopped, including a Transcribe action triggered by the default full-swipe behavior
- **likelihood:** medium — every transcription is one-way, and an occasional mistaken swipe, bulk selection, or change of mind is realistic
- **impact:** unwanted audio download and sustained ANE, battery, and thermal work continue until completion; bulk jobs survive relaunch
- **fix_complexity:** high — active cancellation must coordinate processor task ownership, queue-head/progress cleanup, foreground/background drains, UI states, and concurrency tests
- **recommendation:** open a follow-up issue — the risk merits work, but safe cross-layer cancellation is too broad for this UI PR
- **test_plan:** cover waiting removal, active cancellation, single head advance, progress cleanup, and foreground/background handoff
- **status:** decided
- **decision:** open follow-up GitHub issue
- **follow_up_issue:** https://github.com/jubishop/podhaven/issues/520
