## Findings

### F1: Failed rollback restore leaves a stale restore point that suppresses finish republication  (skipped)

- **severity:** Warning
- **status:** skipped
- **location:** PodHaven/Siri/SiriCatalogPublisher.swift:103-110 (scope: in-diff)
- **concern:** When `databaseDidRollback` fails to rewrite the invalidated file, `lastPublished` stays set, so a later finish-only commit in a within-limit library skips republishing even though no current catalog is on disk. Before this PR, that finish would have republished.
- **resolution:** Skipped. It needs a commit-time SQLite failure after the publisher invalidated the file (no production observer throws in `databaseWillCommit`) and a failed restore write. Disk-full failures tend to cause both, but then republication fails too. Siri fails truthfully until the next non-finish relevant commit or launch. The PR's stated contract covers only failed publications. A one-line fix would need a new regression test and another full-suite run.
