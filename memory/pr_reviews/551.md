### F7: Stale episode finalization can override newer playback  (decided)

- **severity:** Warning
- **architecture:** true
- **confidence:** high
- **location:** PodHaven/Play/PlayManager.swift:552-612
- **scope:** related
- **concern:** finishEpisode keeps using a pre-await episode snapshot and can auto-load after a newer playback request has taken ownership
- **issue:** finalization can clear a newly selected episode or later cancel it with an automatic queue or recommendation load
- **likelihood:** low — user playback must begin during the database or next-episode awaits around a finish, though recommendation lookup can widen that window
- **impact:** an explicit user selection is replaced by stale automatic advancement and the user must retry
- **fix_complexity:** medium — extend ownership through the finish workflow and add a controlled async-boundary regression; a single post-await guard does not cover both windows
- **recommendation:** open a follow-up because the real but narrow user-intent race merits work, while adding another workflow invariant to this already-expanded PR has substantial regression cost
- **test_plan:** suspend next-episode resolution after clear, complete a user-selected load, resume finalization, and assert the selected episode remains current
- **status:** decided
- **decision:** open follow-up GitHub issue
- **follow_up_issue:** https://github.com/jubishop/podhaven/issues/553
