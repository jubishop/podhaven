### F1: limitPodcast could dequeue the currently-playing episode  (closed: withdrawn)
- **severity:** Warning
- **location:** PodHaven/Database/Queue.swift:150 limitPodcast
- **concern:** trim by pubDate could remove the onDeck episode mid-playback
- **outcome / resolution:** withdrawn — PlayManager.cleanUpAfterLoadSuccess dequeues the loaded episode (Queue.swift:348), so onDeck is never `.queued()`; limitPodcast only touches queued rows.

### F2: limitPodcast trims on any feed change, not just on new auto-queue  (closed: fixed)
- **severity:** Warning
- **location:** PodHaven/Database/Repo.swift:281 (updateSeriesFromFeed)
- **concern:** limitPodcast ran whenever queueAllEpisodes!=.never && autoQueueLimit!=nil, with no new-episode guard, so any feed change (metadata edit, existing-episode update) trimmed the podcast's queue even though nothing was auto-queued — contradicting the in-app text and silently dropping manually-queued episodes beyond the limit.
- **resolution:** added `!newEpisodes.isEmpty` to the guard so the trim only runs when an episode was actually auto-queued. Regression test `autoQueueLimitSkippedWhenNoNewEpisodes` (RefreshTests) proven red→green.
- **fixed_at:** 2026-06-01

### F3: routine empty _dequeue debug log from limitPodcast  (closed: fixed)
- **severity:** Nit
- **location:** PodHaven/Database/Queue.swift:150 limitPodcast → _dequeue:186
- **concern:** when a limited podcast has <= limit queued, excessIDs was empty and _dequeue logged "Calling dequeue with empty episodeIDs?" (debug) on every qualifying refresh — a normal path phrased as unexpected.
- **resolution:** `guard !excessIDs.isEmpty else { return }` in limitPodcast before _dequeue. No behavior change (empty dequeue was already a no-op).
- **fixed_at:** 2026-06-01
