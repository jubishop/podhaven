### F5: refresh() restarts the FTS observation on every same-podcast transition (fixed)

- **severity:** Warning
- **architecture:** false
- **location:** EpisodeListFilter.swift (refresh) ← PodcastDetailViewModel.swift transition()
- **concern:** transition() calls refresh() on every observed series change; refresh() restarted the FTS observation whenever filterText was non-empty, even when podcastID was unchanged
- **impact:** with a filter active, playback/finish/queue/refresh re-fire podcastSeriesDetail → transition → restart → redundant GRDB observation teardown+setup + extra filterMethod reassignment (whole-list recompute) per update. Results stayed correct; pure waste.
- **resolution:** added `guard self.podcastID != podcastID else { return }` so only the saved↔unsaved swap (id↔nil) restarts. Live observation already auto-tracks the episode table, so same-podcast updates need no restart.
- **test_plan:** FilterTests.savedDetailFilterDoesNotRestartFTSOnSamePodcastUpdate — settings change drives a same-podcast transition; asserts episodeIDs call count==0 after. Proven failing (actual:1) before the guard.
- **fixed_at:** 2026-06-02

### F6: active filter goes stale after disappear/reappear (fixed)

- **severity:** Warning
- **architecture:** false
- **location:** EpisodeListFilter.swift (cancel/resume) ← PodcastDetailViewModel.swift performAppear()/disappear()
- **concern:** disappear() cancels the FTS observation; reappear never restarts it (refresh() early-returns on unchanged podcastID), so searchFilter freezes on its last id set
- **impact:** @State VM survives a push/pop; with a filter active, episodes matching the query that land after reappear are silently dropped (false negatives) until the user edits the text. Regression vs pre-PR in-memory filter, which recomputed live.
- **resolution:** added `resume()` (restarts only when observationTask==nil && podcastID!=nil && filterText non-empty) and called it from performAppear; pairs cancel-on-disappear with restart-on-appear like recommendationCoordinator. No F5 regression — resume() runs per-appear, not per-transition.
- **test_plan:** FilterTests.savedDetailFilterResumesAfterReappear — type filter → disappear → appear → upsert a matching episode → assert it surfaces. Proven red (stale set dropped it, 11s timeout) → green (0.2s).
- **fixed_at:** 2026-06-02

### F7: saved FTS prefix-match vs unsaved substring-match diverge (skipped)

- **severity:** Nit
- **architecture:** false
- **location:** EpisodeListFilter.swift (restart, saved vs unsaved paths)
- **concern:** same query matches differently saved (FTS `term*` prefix) vs unsaved (in-memory `contains` substring)
- **resolution:** declined. Inherent to in-memory preview vs DB FTS, documented in the header comment; unsaved is a transient pre-subscribe state and most real queries are word-prefix-like.
- **skipped_at:** 2026-06-02
