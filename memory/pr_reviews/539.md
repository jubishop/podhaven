### F7: Load ownership does not cover the transition's terminal state  (decided)

- **severity:** Warning
- **architecture:** true
- **confidence:** high
- **location:** PodHaven/Play/PlayManager.swift:239; PodHaven/Play/PlayManager.swift:298; PodHaven/Play/PlayManager.swift:481
- **scope:** in-diff
- **concern:** Load ownership gates only stale failure cleanup, so the newest load can fail before state mutation while the cancelled predecessor leaves playback without a terminal state.
- **issue:** If load A has cleared on-deck and set loading, load B takes ownership but fails configuration or activation, A skips stop as stale while B has no preflight cleanup, leaving `.loading(A)` and an active audio session with no episode.
- **likelihood:** low — this requires overlap during an asset load plus a second load's preflight failure; long asset loads and background activation failures are both shipped paths, but their alignment is narrow.
- **impact:** The app and widget can show loading with no current episode, and the audio session stays active until another retry or foreground restoration; it is recoverable and does not corrupt data.
- **fix_complexity:** high — F3 and F5 show that ownership must cover cancellation, mutation, and terminal states across the full transition, with deterministic concurrency tests; another branch-local guard would extend fragile coordination state.
- **recommendation:** Open a follow-up issue for a single load-transition state machine; the low expected harm does not justify another local coordination patch in this already complex PR.
- **test_plan:** Suspend A in asset loading, fail B's audio-session preflight, release A, and assert a terminal status, deactivated audio, and recoverable pending request.
- **alternatives:** Targeted preflight cleanup is smaller but preserves the fragmented ownership model that produced the recurring races.
- **decision:** Open a follow-up GitHub issue for a single load-transition state machine.
- **follow_up_issue:** https://github.com/jubishop/podhaven/issues/548
- **decided_at:** 2026-07-26
- **status:** decided
- **source_review_id:** PRR_kwDONT4Ems8AAAABHQjn3g
