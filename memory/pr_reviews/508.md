### F2: Cleared start state suppresses a later download  (decided)

- **severity:** Warning
- **architecture:** false
- **confidence:** high
- **location:** PodHaven/Cache/CacheManager.swift:308
- **scope:** in-diff
- **concern:** clearCache leaves the shared DownloadStart marked cancel after returning, so a later caller can join it and have a fresh claim discarded
- **issue:** a request made after clearCache completes can win a new DB claim but inherit the prior generation's cancel disposition and create no task
- **impact:** an immediate re-download or playback request silently does nothing until the older start participants drain
- **recommendation:** detach or drain the canceled start generation before clearCache returns so later callers receive a fresh proceed state
- **test_plan:** gate the original winning claim, clear it, then assert a post-clear request creates and resumes a task
- **status:** decided
- **decision:** fix in PR

### F3: Completion can outrun clearCache's stale snapshot  (decided)

- **severity:** Warning
- **architecture:** false
- **confidence:** high
- **location:** PodHaven/Cache/CacheManager.swift:209
- **scope:** related
- **concern:** clearCache decides file removal from its initial Episode snapshot while terminal completion can cache the file before cancellation lookup
- **issue:** if completion finishes after the initial read, clearCache finds no live task and returns from the stale nil cachedURL without clearing the newly cached file
- **impact:** the user's remove-download action reports completion but leaves the episode and file cached
- **recommendation:** coordinate with the active attempt's terminal callback, then re-read and clear the current cached filename and file
- **test_plan:** suspend clearCache after its initial episode fetch, finish the task, resume clearCache, and assert the row and file are uncached
- **status:** decided
