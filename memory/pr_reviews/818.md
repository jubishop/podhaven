## Findings

### F1: Launch freshness depends on a manual `policyVersion` bump  (skipped)

- **severity:** Warning
- **status:** skipped
- **location:** PodHaven/Siri/SiriCatalogPublisher.swift:31
- **concern:** A later change to what `publish()` produces, such as selection, omission order, size limit, or write attributes, that forgets to bump `policyVersion` keeps old-policy catalogs across launches until the next relevant commit.
- **resolution:** Skipped: the contract sits beside the publisher and in the docs, format changes already bump `schemaVersion`, and a miss self-heals at the next relevant commit. Keying on `AppInfo.gitCommitHash` instead would drop the manual step for one republish per update, but would reverse a deliberate design for low expected harm.

### F2: `SiriCatalog.init` defaults `source` to nil only for tests  (skipped)

- **severity:** Nit
- **status:** skipped
- **location:** PodHaven/Siri/SiriCatalog.swift:135
- **concern:** Production always stamps a source, so the `source: Source? = nil` default serves only test fixtures, against the rule on test-only production surfaces.
- **resolution:** Skipped: `nil` models a real unstamped file from earlier versions, omitting it fails safe by forcing a republish at the next launch, and requiring it would only add noise to existing fixtures.

### F3: A failed publication leaves an older rollback restore point  (skipped)

- **severity:** Warning
- **status:** skipped
- **location:** PodHaven/Siri/SiriCatalogPublisher.swift:72, :191
- **scope:** related
- **concern:** After a publication fails, `lastPublished` still holds the previous catalog, so a later rolled-back relevant commit restores a snapshot older than the committed library.
- **resolution:** Skipped: pre-existing and not worsened; it needs a failed publication and then a failed relevant commit in one process, usually both from disk exhaustion, when the restore write also fails. The new stamp makes the next launch republish.
