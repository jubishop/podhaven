## Findings

### F1: Whitespace-free text defeats URL-detection windows  (decided)

- **severity:** Warning
- **architecture:** false
- **confidence:** high
- **location:** PodHaven/Views/Components/HTMLContent.swift:343
- **scope:** in-diff
- **concern:** Each link-detection window ends at the first whitespace after its 16K limit, so text with none sends the whole rest of the description to NSDataDetector in one scan.
- **issue:** In the test host, one whitespace-free scan of `http://a.co|` or `http://a.co,` links costs about 0.003 s and 0.3 s of CPU at 32K characters but about 12 s at 64K; the PR's windowing doesn't bound it.
- **likelihood:** low — needs a hostile or malformed description and the user opening its detail view
- **impact:** the description never renders while a background thread burns CPU for minutes per open
- **fix_complexity:** low — end each window at its last whitespace before the limit, or at the limit when it has none, plus one CPU-budget test case
- **recommendation:** fix in this PR — the PR states URL detection is bounded against hostile content
- **test_plan:** `HTMLLinearTimeTests.linkingURLsWithoutWhitespace` with `|` and `,` separators, 20,000 links each; show it over budget before the fix, then rerun the suite and `bin/test-all --ensure --revision <sha>`
- **status:** decided
