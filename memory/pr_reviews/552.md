### F7: Interruption removal can diverge durable and in-memory membership (fixed)

- **severity:** Warning
- **architecture:** false
- **confidence:** high
- **location:** PodHaven/Transcriptions/TranscriptionQueue.swift:270-288,309-327
- **scope:** in-diff
- **concern:** pause and discard release `persistenceLock` after durable removal but before projecting that removal in memory
- **issue:** a same-episode enqueue already waiting on the lock can reinsert durably before the older interruption removes every in-memory copy
- **likelihood:** low — normal status gates suppress most overlaps, but concurrent enqueue actions can pass their checks before the first insert and then overlap a pause or discard
- **impact:** the durable row becomes invisible and unprocessable until restart; another enqueue deduplicates against storage and cannot repair the current process
- **fix_complexity:** low — hold the existing lock through both projections and add one focused lock-order regression; no schema or API change
- **recommendation:** fix in this PR because the consistency failure is recoverable but the invariant repair is local and low-cost
- **test_plan:** queue an enqueue behind interruption removal and assert durable and projected membership remain identical
- **status:** fixed
- **decision:** fix in this PR
- **outcome:** pause and discard now retain the persistence claim through durable removal and in-memory projection; a gated waiting-enqueue regression covers both modes
- **fixed_at:** 2026-07-27
- **source_review_id:** PRR_kwDONT4Ems8AAAABHaruIA
