## Findings

### F1: A paused reload that fails empties On Deck  (fixed)

- **severity:** Warning
- **status:** fixed
- **scope:** in-diff
- **location:** PodHaven/Play/PlayManager.swift:192
- **concern:** `load()`'s catch skipped the recovery presentation and failed-restore recovery whenever the revision changed. A remote pause or toggle now reaches a reload, so if that reload then fails, On Deck empties, the episode moves to Up Next, and no alert shows. Before this PR the pause waited behind the reload.
- **resolution:** the catch now also restores when the load task wasn't cancelled, because only a load-replacing claim cancels it. Regression: `remoteCommandDuringFailingReloadKeepsEpisodeOnDeck`, 6 cases.
- **fixed_at:** 2026-11-25

### F2: A second play supersedes a recovery reload  (fixed)

- **severity:** Warning
- **status:** fixed
- **scope:** in-diff
- **location:** PodHaven/Play/PlayManager.swift:620
- **concern:** a play during a recovery reload's audio-session setup, while On Deck still holds the episode, started a new request instead of joining. The reload restarted, and if the first reload finished during the second's lookup, neither one played. Remote plays no longer wait behind the reload, so a double press can now hit this.
- **resolution:** the join now also covers a load of the recovery episode. Regression: `secondPlayDuringRecoveryReloadJoinsIt`, 2 cases.
- **fixed_at:** 2026-11-25
