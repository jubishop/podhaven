### F1: Any route loss during an interruption forfeits its resume  (fixed)

- **severity:** Warning
- **status:** fixed
- **scope:** in-diff
- **location:** PodHaven/Play/PlayManager+RouteChangeRecovery.swift:150
- **concern:** If iOS reports a call's Bluetooth or CarPlay profile switch (A2DP to HFP) as `.oldDeviceUnavailable`, every such call would leave playback paused where `main` resumes it, a common path traded for the rare headphone loss mid-call.
- **resolution:** The forfeit now requires the current route to hold only `.builtInSpeaker` or `.builtInReceiver` outputs, or none; a parameterized test failed on the PR head for HFP and CarAudio routes and passes with the fix.
- **fixed_at:** 2026-11-27
