# Episode Transcription

On-device transcription of individual episodes, initiated manually or through a per-podcast new-episode opt-in and rendered read-only in `EpisodeDetailView`. iOS 26+. Interactive tap-to-seek is a documented v2. Supersedes — for v1 — the autonomous three-tier design in [Episode Transcripts](transcripts.md) (abandoned).

## Status

The backend transcription runtime from #461, episode projection support from #507, and view integration from #516 are merged into `main`. The on-device `Transcriber` (real speech model) and the `BGProcessingTask` runtime behaviour are integration/device-tested, not in CI; both sit behind protocols/fakes so everything around them is unit-tested. The transcript renders read-only — **interactive playback (tap-to-seek, active-segment highlight, auto-scroll) is deferred to v2**; the per-segment timestamps are already stored, so v2 is purely a UI layer. Smart Lists can filter by transcript presence and phrase content through a local FTS5 index. Timed Podcasting 2.0 publisher transcripts now feed the same storage and display path. Still deferred and tracked in [Episode Transcripts](transcripts.md): speaker diarization, global transcript search outside Smart Lists and summaries, and autonomous working-set transcription beyond the explicit per-podcast opt-in.

## Why

Transcription is expensive — roughly 5× realtime of Neural-Engine compute (~12 min for an hour episode) — so requests remain explicitly user-directed: people either select episodes manually or opt individual podcasts into queueing newly discovered episodes. Work drains one episode at a time through a bounded queue; the app does not autonomously choose a broader working set. The immediate value: read an episode you can't listen to now. Every segment is timestamped, so a v2 can turn the static transcript interactive — tap a line to jump playback there, with highlight + auto-scroll — without re-transcribing; the timing is already stored.

## Scope

In:
- On supported devices, a manual "Transcribe" action on every episode surface: detail toolbar, detail body, list context menu, swipe action, multi-select. The feature stays hidden until en-US support is positively confirmed.
- A persisted, termination-surviving queue and durable per-episode checkpoints that transcribe one episode at a time off the main actor.
- On-device transcription via iOS 26 `SpeechAnalyzer`/`SpeechTranscriber` against the cached audio file, producing timestamped segments.
- Timed segments stored as JSON in a single new optional `episode.transcript` TEXT column (nil = no transcript).
- Description and Transcription segmented tabs in `EpisodeDetailView`, with a read-only transcript render.
- Per-episode transcription state (queued / transcribing / paused / transcribed / failed) in the detail view, with action availability kept live across the other episode surfaces.
- Smart List state filters for transcribed/not-transcribed episodes and transcript text contains/exclude filters.
- A dedicated Settings → Transcription Queue manager with drag reordering, move-to-edge and removal swipe actions, multi-selection, live active progress, and durable checkpoint progress for paused work.
- A capability-gated per-podcast opt-in that queues episodes newly discovered during refresh as one batch, with non-fitting batches dropped under the warning shown in Podcast Settings.
- Timed Podcasting 2.0 JSON, WebVTT, and SubRip imports that pre-empt redundant on-device work while ignoring speaker metadata and untimed resources.

Out (deferred — see [Episode Transcripts](transcripts.md)):
- Interactive transcript: tap-a-line-to-seek, active-segment highlight, auto-scroll. v1 renders read-only; the per-segment timestamps are persisted, so v2 is a pure UI layer (no re-transcription).
- Speaker diarization (no first-party API; FluidAudio is the documented v2 path).
- Autonomous / opportunistic transcription of a working set beyond the explicit per-podcast new-episode opt-in.
- Global transcript search outside Smart Lists and on-device summaries.
- Multi-locale: v1 is en-US only, gated on model availability.

## Key decisions

- **Timed JSON in one finished-transcript column, not a segment table.** `SpeechTranscriber` yields per-segment time ranges via the `.audioTimeRange` attribute option. We serialize `[TranscriptSegment]` (start, end, and text) as JSON into the optional `episode.transcript` TEXT column. v1 renders this read-only, but the timing lets v2 add tap-to-seek/highlight without re-transcription. The checkpoint table stores only resumable work state; it does not normalize final segments into SQL rows. Smart List phrase filtering flattens the segment text into a separate FTS5 index without changing this source-of-truth shape. These fields can later migrate without loss to a real `transcript_segment` table if segment-addressable search or diarization needs one. Diarization still requires a fresh second pass because no speaker data exists in the JSON.
- **Discretionary `BGProcessingTask` for background drain (not `BGContinuedProcessingTask`).** We mirror `EmbeddingProcessor`: a foreground background-priority `Task` drains while the app is open, and a registered `BGProcessingTask` lets iOS drain the queue opportunistically when backgrounded. iOS 26's `BGContinuedProcessingTask` was evaluated and rejected — it surfaces a user-facing **Live Activity** (heavyweight/odd for "transcribe an episode"), it's flagged **Beta**, and it had notable reliability reports at the 26.0 launch. The foreground task preserves its in-flight analyzer across ordinary scene backgrounding, so suspension and reactivation continue the same attempt instead of restarting it. If the episode finishes while the app remains backgrounded, the foreground drain releases ownership so a granted background task can process the remaining queue. True background-task expiration or process termination loses at most the active audio chunk: each completed chunk is persisted, and the next grant resumes with an overlap before the checkpoint.
- **Queue and checkpoints persisted in SQLite.** The ordered queue is an `episodeTranscriptionQueue` table with unique episode IDs, cascade deletion, and monotonic positions. `TranscriptionQueue` loads that order once into its observable in-memory projection, then applies successful mutations incrementally; routine removals delete one row without refetching the backlog. SQLite also stores the larger correctness-critical checkpoint payload atomically so completed speech survives termination, app upgrades, and background-task expiration.
- **Bounded admission, never destructive enforcement.** `maxTranscriptionQueueLength` defaults to 50 and is configurable from 10 through 100 in steps of 10. Capacity includes the active item and all waiting items. New unique IDs are admitted transactionally as an all-or-nothing batch; duplicates already in the queue consume no extra capacity. A rejected request throws `TranscriptionQueueError.capacityExceeded` and every episode-detail, list, context-menu, swipe, and multi-select caller presents the native **Transcription Queue Full** alert. Per-podcast automatic refresh requests instead log and drop the rejected batch because their settings UI warns that full-queue work is not retried. Lowering the setting or importing a larger legacy queue preserves all existing work and rejects new unique work until the whole request fits.
- **Default-hidden device capability gate.** `TranscriptionAvailability` starts unknown, checks the en-US `SpeechTranscriber.supportedLocales` catalog when the app enters the foreground, and exposes the feature only after a positive result. Unknown and unsupported states render no transcription tabs, buttons, menus, bulk actions, or swipe-setting options. The processor keeps its own support check as a defensive boundary for persisted work.
- **Diarization deferred to v2.** No first-party Apple diarization. FluidAudio (CoreML pyannote, ANE, iOS 17+) is the path; pickup notes live in [Episode Transcripts → Speaker diarization](transcripts.md#speaker-diarization-deferred). Publisher JSON may carry speaker labels, but the current importer intentionally ignores them to preserve the speaker-free segment model.

## Data model

- **Migration v67** (`PodHaven/Database/Migrations/Migration_v67.swift`, registered `"v67"` in `Schema.makeMigrator()`): `ALTER TABLE episode ADD COLUMN transcript TEXT` — nullable, default NULL, no backfill. Does not trip the `episode_content_updated` trigger (which fires only on title/description change). Migration test `v67Tests.swift` migrates through `"v66"` before asserting the new column.
- **Migration v70** (`PodHaven/Database/Migrations/Migration_v70.swift`, registered `"v70"`): clears the pre-release finished transcripts that lack required segment end times, then adds `episodeTranscriptionCheckpoint`, keyed to `episode.id` with cascade deletion. Its validated JSON holds completed segments, the committed audio time, total duration, locale, and audio fingerprint.
- **Migrations v73–v74:** v73 creates `episodeTranscriptionQueue(position, episodeId)` with unique IDs and episode cascade deletion, then imports the legacy defaults array in first-seen order while filtering duplicates and missing episodes. It preserves oversized legacy queues rather than silently dropping requested work. v74 removes the old `transcriptionQueue` defaults key only after v73 has committed, making cleanup retry-safe; malformed legacy data imports no rows and is then cleaned up.
- **Migration v76:** adds the non-null `podcast.alwaysTranscribeNewEpisodes` opt-in, defaulting existing and new podcasts to false.
- **Migration v77:** creates `episode_transcript_fts`, backfills flattened `segments[].text` for existing transcripts, and installs insert/update/delete triggers keyed by episode id. Phrase matching can cross adjacent timed segments without indexing the persisted JSON metadata.
- **Migration v79:** adds nullable JSON columns for publisher transcript references and the chosen-source provenance. A NULL reference payload marks a pre-v79 episode whose feed metadata has not yet been observed; refreshed and newly inserted episodes persist `[]` for a known empty reference set. This distinction lets the first post-upgrade refresh record historical references without eagerly downloading an entire back catalog. References remain available for deferred retrieval without reparsing the original feed.
- **Model:** add `transcript: String?` to `UnsavedEpisode` and `Column("transcript")` to `Episode.Columns`, with a computed `decodedTranscript: Transcript?` that lazily caches its decoded value in memory while persisting only the original JSON.
- **Codable payload:** `TranscriptSegment` requires start/end timing plus text; `Transcript` carries the finished segments, locale, and creation date. `TranscriptionCheckpoint` carries the accumulated segments plus resume compatibility fields. Segment end times let overlap replacement remove a segment that crosses the checkpoint boundary without duplicating its text. Future persisted-payload changes require an explicit database migration that rewrites or clears existing JSON.
- **Repo:** checkpoint read/save/delete operations use GRDB records. `updateTranscript(_ id:transcript:)` writes an explicit replacement and clears publisher provenance. Publisher and on-device completion use one conditional write that stores only while `episode.transcript` is NULL and deletes the checkpoint in the same transaction.

## Transcription engine — `PodHaven/Transcriptions/`

- **`Transcriber` service**: wraps `SpeechAnalyzer` + `SpeechTranscriber(locale:, attributeOptions: [.audioTimeRange])` behind app-owned speech protocols and analyzes deterministic two-minute chunks. After each chunk, it merges finalized results into a `TranscriptionCheckpoint` and awaits durable persistence before advancing. A resumed chunk starts ten seconds before the committed audio time; fresh timed segments replace the overlap, including any prior segment whose end crosses that boundary. The custom audio input sequence seeks the cached file to the requested frame range, converts buffers to the analyzer's preferred format, and gives the first `AnalyzerInput` its absolute source time so result timestamps remain episode-relative. The range's latest result end over total duration drives monotonic progress. Work stays off MainActor.
- **Model availability gates** via the speech model-manager seam: the shared UI capability starts hidden and appears only after en-US support is confirmed; the processor independently rejects unsupported hardware/locales before acquiring episode audio. It then checks installed locales and installs the en-US model when missing. en-US only in v1.
- **Audio dependency:** on-device transcription needs the **local** file, not the stream. The processor ensures the episode is cached via `CacheManager.cachedURL(downloadingIfNeeded:)`, which starts or joins the cache download through an `AsyncLatch`, then transcribes the returned cached file URL.

## Queue, processing & state

- **`TranscriptionQueue`** (cached Factory service, `fileprivate init`): loads the ordered GRDB queue once and publishes it through `@Broadcasted var episodeIDs: [Episode.ID]`; successful enqueue, removal, and failure mutations update that projection incrementally, while an explicit reorder validates and rewrites the exact durable membership transactionally. A head-only `AsyncStream<Episode.ID>` yields the current item and advances after it is removed, failed, or moved away from the head, replaying a retained head when a lifecycle handoff starts a new stream. `@Broadcasted var progress: [Episode.ID: Double] = [:]` carries active progress; `@Broadcasted var interruptions: [Episode.ID: TranscriptionInterruption] = [:]` distinguishes observable cooperative pause and discard cleanup; `@Broadcasted var failed: Set<Episode.ID> = []` is transient and cleared on retry. Durable mutations are asynchronous and serialized, while interruption intent is marked before waiting so duplicate requests are idempotent and the processor revalidates whether waiting work promoted to active before deciding which task to cancel.
- **`TranscriptionProcessor`** (cached service, mirrors `EmbeddingProcessor` conventions): one `for await episodeID` loop consumes the queue's head-only work stream, first tries persisted publisher references in JSON, VTT, then SRT order, and otherwise ensures audio, loads any compatible checkpoint, runs `Transcriber`, persists each completed chunk, writes the finished transcript, and dequeues — strictly one at a time. Publisher downloads use a dedicated fast-fail session so unavailable remote candidates do not hold up cached on-device work while offline. Successful publisher import removes redundant queue/checkpoint state and cooperatively cancels an already-active on-device attempt. The conditional transcript write makes an import-versus-completion race deterministic without replacement. Foreground and background entry points serialize on shared drain ownership, while an explicitly owned per-episode task lets a user pause or discard active work. Pausing or removing waiting work only removes its scheduling state. Pausing active work immediately removes the persisted head, cooperatively stops the analyzer, clears live progress, and retains the last durable checkpoint for a later resume. Moving the active item away from the head uses the same retained-checkpoint pause before processing the new head. Checkpoint deletion belongs only to the separately confirmed Discard Progress action, which also stops and removes active or queued work before deleting. Ordinary scene backgrounding and task expiration retain the active head for resume. Failures are recorded and dequeued while their durable checkpoint remains available for an explicit retry. If that durable queue mutation fails, the processor retains the row, clears live progress, and schedules a later attempt instead of reclassifying the storage error or retry-looping in the foreground. A background drain also releases its current grant after retaining the head so it does not wait for expiration before the scheduled retry. The work source is the **persisted queue**, not the embedding processor's persisted demand signal plus DB-derived backlog; this queue knows the exact ordered IDs to process.
- **Background drain:** `TranscriptionProcessor` owns a `BackgroundTaskScheduler(identifier: "\(AppInfo.bundleIdentifier).transcription", cadence: .minutes(1), taskType: .processing(...))` (new identifier in `BGTaskSchedulerPermittedIdentifiers`; the `processing` background mode is already declared). `register()` — called from `AppLauncher`, mirroring `embeddingProcessor.register()` — installs a handler using the same processor loop in a bounded-until-empty mode. Both processors use the scheduler's on-demand mode: registration submits only when persisted work exists, backgrounding schedules while work remains, and draining the last item cancels the successor request. The one-minute value is only the earliest begin date for real work; no request is kept pending for an empty queue. On expiry the handler explicitly finishes the analyzer, completes `false`, and retains both the queue head and the last committed checkpoint. The next grant or activation resumes from the overlap before that checkpoint.
- **Diagnostics:** `transcriptionTelemetry` log events share a per-drain `runID`, mode, and episode ID. Background-run, episode, model-download, chunk, checkpoint, and final-storage events record wall time and durable audio position; chunk completion also records new/overlap/analyzed audio seconds and the audio-to-wall throughput ratio. A terminated run can therefore be reconstructed from its last chunk event and last `checkpointPersisted` event in an attached NDJSON log.
- **Per-episode status (mirrors caching's `Episode.CacheStatus` + `downloadProgress`):**

  ```swift
  enum TranscriptionStatus {
    case none, queued(position: Int, total: Int), transcribing(Double), paused(Double)
    case pausing, discarding, transcribed, failed
  }
  ```

  derived like `Episode.CacheStatus.from(...)`:
  - `.transcribed` ⟸ the caller reports a usable stored transcript (presence on rows; successful decode in detail)
  - `.pausing` / `.discarding` ⟸ `interruptions[id]` while cooperative cleanup finishes
  - `.transcribing(p)` ⟸ id is the active item (`transcriptionProgress[id]`)
  - `.queued(position:total:)` ⟸ the id's one-based index and current depth in the ordered queue
  - `.failed` ⟸ `failed.contains(id)`
  - `.paused(p)` ⟸ the episode has a durable checkpoint but no active or queued work
  - else `.none`

  A `transcriptionStatus(for:)` accessor drives detail presentation and action eligibility on every surface. Queue, progress, and interruption state are `Broadcast`s, while Episode Detail observes checkpoint persistence directly, so all stay live without adding transcription indicators to episode rows.

## UI integration

- **Queue manager:** Settings exposes Transcription Queue only after the same device-capability gate used by the episode actions succeeds. The Transcription section also provides an accessible adjustable maximum from 10 through 100 and explains that lowering it preserves existing work. The actively transcribing episode floats above the waiting backlog in a safe-area inset with live progress. Waiting rows show durable checkpoint progress and mirror Up Next actions: leading-edge removal and move-to-top/bottom reorder only the backlog, while trailing-edge Transcribe Now promotes that episode to the active head and requeues the interrupted transcription first. Dragging and multi-selection also reorder only waiting work. Removal pauses/removes scheduling while retaining partial checkpoints, so later re-enqueueing resumes instead of starting over. The view has a populated Xcode preview so row states and interactions can be developed without running a transcription.
- **Per-podcast automatic transcription:** Podcast Settings exposes a capability-gated opt-in that submits episodes discovered during refresh as one queue batch. Its visible warning explains that enabling many podcasts can saturate the queue and that rejected automatic work is dropped without retry. Existing episodes and first-time subscription imports are unaffected.
- **Detail body:** a full-width segmented `Picker` switches between Description and Transcription. The Transcription tab shows a CTA when `.none`; exact queue position and Pause when `.queued`; a determinate progress bar with separate Pause and Discard Progress buttons when `.transcribing` (an indeterminate spinner before progress climbs above 0); durable percentage with separate Resume and Discard Progress buttons when `.paused`; phase-specific cleanup indicators when `.pausing` or `.discarding`; the rendered read-only transcript when `.transcribed`; decode recovery for unreadable stored JSON; and an error + retry when `.failed`. Discard Progress uses a destructive confirmation dialog before checkpoint deletion.
- **Detail toolbar:** a `ToolbarItem(.primaryAction)` inserted between `ShareEpisodeButton` and the rating `Menu`, so the trailing group reads `[rating] [transcription] [share]` (primaryAction lays out right-to-left). The action starts or resumes transcription when idle/paused, changes to an accessible pause action while queued or active, and stays disabled while cooperative pause or discard cleanup finishes; detailed progress and the destructive discard affordance remain in the Transcription tab.
- **Shared actions:** add `transcribeEpisode(_:)` to the `ManagingEpisodes` protocol (decl + default impl) → instantly available in the list **context menu** and **swipe actions**; add `transcribeSelectedEpisodes()` to `SelectableEpisodeList` → the **multi-select** batch menu. Enqueue is gated by status (skip already-transcribed/queued/transcribing). `EpisodeDetailViewModel` does not adopt `ManagingEpisodes`, so it gets its own `transcribe()` method.
- **Swipe option in Settings:** add `case transcribe` to `EpisodeSwipeAction` plus its three exhaustive-switch sites (`icon(for:)`, `trailingAction(_:)`, and `isAvailable(_:)`). The option is absent until device support is confirmed, and `isAvailable` hides the configured row action once an episode is transcribed/queued. ("Swipe left" = the trailing-edge actions this codebase models as `trailingAction`.)
- **Icon:** add `AppIcon.transcribeEpisode`, plus pause/resume/discard variants for the detail controls.
- **Interactive playback (deferred to v2):** tap-a-segment-to-seek + active-segment highlight + auto-scroll. The plumbing is ready: tapping would use `EpisodeDetailViewModel.loadAndPlay(_:seekTo:)` (seek if on-deck, else load-then-seek), and highlight/auto-scroll would bind to `PodAVPlayer.currentTimeStream` / `sharedState.onDeck?.currentTime`, selecting the active segment by start time. v1 renders read-only; the per-segment timestamps are already persisted.
- **Optional row glyph:** a small "has transcript / transcribing" indicator in `EpisodeListView` rows, alongside the cache indicator, for at-a-glance state.

## Phased build plan

1. **Schema + model** — Migration v67, `transcript` column + `Episode.Columns`, `Transcript`/`TranscriptSegment` Codable, `Repo.updateTranscript`, migration test. (Foundation; nothing user-visible.)
2. **Engine** — `PodHaven/Transcriptions/Transcriber` + speech model gate + the awaited `cachedURL(downloadingIfNeeded:)` cache helper. Unit-tested behind speech-framework protocol seams with fakes.
3. **Queue + processor (foreground)** — `TranscriptionQueue` (persisted) + `TranscriptionProcessor` loop, one-at-a-time, status/progress broadcasts. Tests with speech/cache fakes.
4. **UI** — detail tabs and read-only transcript, toolbar button, `ManagingEpisodes`/`SelectableEpisodeList` actions, context menu, swipe case + settings, multi-select, `AppIcon`, and live action gating across surfaces.
5. **Background drain + durable resume** — `BGProcessingTask` via the existing `BackgroundTaskScheduler`, plus ranged analysis and SQLite checkpoints that bound expiration loss to the active chunk; unit-tested with `FakeBGTaskScheduler`.
6. **Queue manager** — a capability-gated Settings destination with dedicated progress rows, reorder/remove swipe actions, drag editing, multi-selection, active-work requeue, and retained checkpoints for removed work.

Phases 1–3 are independently shippable; 4 makes transcription usable; 5 completes durable background processing; 6 makes the ordered work user-manageable. (Interactive playback — tap-to-seek / highlight / auto-scroll — is deferred to v2.)

## Testing

- Migration test (`v67Tests.swift`) — raw SQL, migrate `upTo: "v66"` then `"v67"`, assert the column.
- Queue persistence and capacity: ordered enqueue/deduplication, atomic near-capacity rejection, settings decrease, service recreation from GRDB, cascade deletion, and removal from a 10,000-item projection without a second full fetch. Migration tests cover first-seen order, duplicates, missing episodes, malformed data, oversized input, and post-commit defaults cleanup.
- Processor loop: speech/cache fakes drive one-at-a-time ordering, foreground/background exclusivity, progress, waiting and active pause, explicit active discard, cleanup, single queue advancement, failure, unsupported-device preflight before audio acquisition, stale-download recovery, and on-demand background scheduling. Durable-removal regressions prove that both completed and failed transcriptions retain their queue row, clear live progress, avoid a foreground retry loop, and release a background grant for the scheduled retry when storage fails. A pause handoff regression proves that a background grant takes the remaining queue after a foreground head is paused. A two-grant expiration regression proves that the first grant commits a chunk, expires during the next, and the second resumes from the overlap before producing one deduplicated final transcript.
- Cancellation races: deterministic persistence and analyzer latches prove overlapping active pauses cancel once and clear `.pausing` only after cooperative cleanup, and that a waiting item promoted while durable removal is pending is revalidated and cancelled as the active item.
- Queue management: exact-permutation persistence and head-stream updates; the active item floats outside the waiting backlog; ordinary waiting reorders preserve the active head; Transcribe Now safely requeues that head and promotes the selected episode; single and multi-item removal retain partial checkpoints; view-model hydration preserves queue order while combining live and durable progress; hosted accessibility inspection verifies progress and queue actions.
- Episode Detail: checkpoint observation surfaces paused percentage; pause/resume retains and requeues work; only the explicit discard action deletes the checkpoint; action labels distinguish Pause, Resume, and Discard Progress for VoiceOver.
- Migration v70 tests verify destructive legacy-transcript cleanup, checkpoint shape constraints, and episode cascade deletion.
- Status derivation: each `TranscriptionStatus` branch.
- `Transcriber` against the real model is integration-only; production stays behind the protocol so units use the fake.

## Known follow-ups

- **Audio retention (decided):** transcription downloads audio if absent via `CacheManager.cachedURL(downloadingIfNeeded:)`. Manual and automatic cache removal protect only the actively transcribing episode; waiting queue entries remain eligible and download again when processing reaches them.
- **Failure surfacing (UI follow-up, with a gap):** the Transcription tab shows an inline "Transcription failed" + Retry; `failed` is transient (cleared on retry or relaunch). Open gap: there is no explicit dismiss affordance, so a user who won't retry can't clear the failed state from the UI.
- **Background-grant timing & thermals (open):** `BGProcessingTask` grants are discretionary and can be delayed; the on-demand request's `.minutes(1)` earliest begin date and `requiresExternalPower = false` are tunable once device-tested (transcription is ~5× realtime, so thermal-gating to charging is a possible future knob). Foreground and background drains share exclusive ownership, and durable chunk checkpoints make repeated grants cumulative, but iOS still controls when those grants occur.
